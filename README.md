# Выбор тарифа Google One через Frida

Да, Google One прячет лучшие предложения. Нет, мы не будем с этим мириться.

На Android-устройстве с root-доступом скрипт подключается к процессу Google One и открывает в Google Play экран оформления выбранного тарифа. Дальше — только ты: **подписку подтверждает сам пользователь, скрипт ничего сам не покупает.**

Для работы нужны три простые вещи: root-доступ, установленное приложение Google One и вход в аккаунт Google на устройстве. Остальное `main.py` сделает сам: настроит подключение через ADB и при необходимости докинет на устройство `frida-server` и `module_521.apk`.

## Запуск — быстро и без магии

```powershell
python -m pip install -r requirements.txt
python main.py
```

```powershell
python main.py --plan helium_1m          # Оформить новую подписку
python main.py --renew --plan pro_6m     # Продлить существующую подписку
python main.py --serial emulator-5560    # Явно выбрать устройство
```

Запустил, выбрал тариф, подтвердил на устройстве — готово. Если что-то пошло не так, читай дальше, там как раз про главный затык.

## Меню — четыре группы, без воды

Тарифы разделены на четыре группы — **Plus**, **Pro**, **Ultra 5x** и **Ultra 20x**. Список берётся из `PLANS` в файле `frida.js`, так что меню всегда в sync со скриптом.

| Ввод | Действие |
|---|---|
| Номер или название тарифа | Открыть экран оформления в Google Play |
| `s` | Переключиться между новой покупкой и продлением (`STACK`) |
| `a` | Добавить тариф YouTube |
| `e` | Повторить проверку и подготовку окружения |
| `g` | Перезапустить Google One и заново загрузить скрипт в процесс приложения |
| `q` | Выйти |

Свежие находки уже в списке: бесплатные триалы Ultra — `ultra5x_12m` (`g1.play.20tb`, `eft-12month`, 12 месяцев бесплатно) и `ultra20x_12m` (`g1.play.ai.pro`, `eft-12mo`, тоже 12 месяцев бесплатно). Play решает по аккаунту, так что если один оффер дал `no_offer`, пробуй соседний — это нормально.

Полный каталог всех тарифов — [SKU-LIST.ru.md](SKU-LIST.ru.md): 109 записей, 94 уникальных SKU, таблицы по тарифам, отдельный список бесплатных и списки для копирования. Сгенерирован из `frida.js`, так что со скриптом не расходится.

## Главный затык: su, или почему frida-server опять не root

Вот это мы забывали раз за разом, поэтому пишу большими буквами.

`main.py` сам запускает `frida-server`, но запускает его как `shell`, а не как root. А attach к Google One без root — `PermissionDeniedError`, и всё тут.

Правильный порядок такой, и никак иначе:

1. Запусти `main.py` первый раз. Он упадёт с `PermissionDeniedError`. Это нормально, не паникуй.
2. Убей его сервер и запусти от root:
   ```bash
   adb -s emulator-5554 shell su -c 'killall -9 frida-server'
   adb -s emulator-5554 shell su -c '/data/local/tmp/frida-server -D &'
   adb -s emulator-5554 shell ps -A | grep frida-server
   ```
   В первой колонке должно быть `root`, а не `shell`.
3. Запусти `main.py` второй раз, с тем же планом. Второй раз он увидит, что сервер уже запущен от root, и не будет его перезапускать — attach пройдёт.

Проверка до запуска не помогает: `main.py` всё равно запустит свой, shell. Только так, в два захода.

И да, `adb shell su -c id` должен дать `uid=0(root)`. Если даёт `Permission denied`, иди в Magisk → Superuser → Shell → Grant, и успей нажать Grant за 10 секунд.

## Новая подписка и продление

В `frida.js` переменная `STACK` определяет режим работы:

```js
var STACK = false; // Новая подписка
var STACK = true;  // Продление существующей подписки Google One (ReplacementMode = 5)
```

По умолчанию выбрана новая подписка. Для продления используется клавиша `s` в меню или параметр `--renew` в командной строке. В текущем аккаунте должна быть действующая подписка, для которой доступно продление.

## Хочешь только посмотреть, что Play предлагает? Есть probe-one.js

Не хочешь ничего покупать, а просто узнать живые офферы? Для этого есть отдельный скрипт `probe-one.js` — он только ловит лог, ничего не оформляет.

```bash
frida -U -p <pid Google One> -l probe-one.js --no-pause
```

Нажми Upgrade в Google One и смотри строки `[probe] offer product=... offerId=...`. Полный токен в лог не пишется, только первые 12 символов — так спокойнее.

А если прогнать весь список разом — есть `scan-offers.sh`. Он берёт все 109 офферов из `offers.txt`, по одному подставляет их в `probe-single.js` и спрашивает у Play только через `queryProductDetailsAsync`, с задержкой 5 секунд между офферами и прогрессом в терминале (`[12/109] ... -> live/missing/error`). Экран оформления не открывается и ничего не покупается — это анализ, а не оформление. Итог — в `scan-results-<дата>.log`.

```bash
./scan-offers.sh                          # все 109, задержка 5 секунд
./scan-offers.sh --serial emulator-5554   # явно выбрать устройство
./scan-offers.sh --start 40               # продолжить с 40-го оффера
./scan-offers.sh --dry-run                # только показать список, ничего не запускать
```

Важно: не гоняй в цикле `main.py --plan` — он открывает экран оформления (`launchBillingFlow`), и каждый такой вызов может сжечь право на триал, даже без нажатия «Подписаться». Для перебора — только `scan-offers.sh`.

## Что скрипт делает автоматически

1. Ищет ADB в `PATH`, Android SDK и каталоге установки MuMu.
2. Если устройств нет, перезапускает сервер ADB и пробует подключиться к стандартным портам эмуляторов MuMu, LDPlayer и Nox.
3. Если одно устройство обнаружено несколько раз, объединяет записи. При выборе отдаёт предпочтение устройству с root-доступом, установленным Google One и выполненным входом в аккаунт Google.
4. Если на компьютере отсутствует Frida, устанавливает `frida-tools` через pip.
5. Если на устройстве отсутствует `/data/local/tmp/module_521.apk`, декодирует модуль из `module_b64.py` и копирует его через ADB.
6. Если на устройстве отсутствует `frida-server` или его версия отличается от версии Frida на компьютере, берёт сервер из `assets/` либо загружает с GitHub, затем запускает его на устройстве. Помни про затык с su выше — этот шаг как раз про него.

## Файлы проекта

| Файл или каталог | Назначение |
|---|---|
| `main.py` | Точка входа. Подготавливает окружение, выводит меню и загружает скрипт в процесс приложения |
| `frida.js` | Скрипт Frida с таблицей тарифов и кодом для работы с BillingClient |
| `probe-one.js` | Отдельный логгер: ловит живые sku/offer из BillingClient, ничего не покупает |
| `scan-offers.sh` | Прогоняет все 109 офферов из `offers.txt` по одному (5 секунд между ними), только чтение, итог в `scan-results-<дата>.log` |
| `probe-single.js` | Шаблон для одного оффера: `queryProductDetailsAsync` для одного sku, без `launchBillingFlow` |
| `offers.txt` | Список всех офферов: ключ, sku, offer — сгенерирован из `frida.js` |
| `module_b64.py` | DEX-модуль BillingClient 5.2.1 в кодировке Base64 |
| `requirements.txt` | Зависимости Python |
| `assets/` | Локальный кеш файлов `frida-server` |

На устройстве используются следующие пути:

- `/data/local/tmp/module_521.apk`
- `/data/local/tmp/frida-server`

Подробнее про безопасность — в [SECURITY-MANUAL.ru.md](SECURITY-MANUAL.ru.md), а первый запуск с нуля — в [USER-GUIDE.ru.md](USER-GUIDE.ru.md). Да, их тоже стоит прочитать, они короткие.
